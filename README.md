# SMART PAPS — 독립 웹사이트 버전

중학교 체육수업용 PAPS(팝스) 실시간 기록·랭킹 관리 프로그램입니다. 기존 Claude 아티팩트
(`paps_dashboard.jsx`)를 React + Firebase(Firestore) 기반의 독립 웹 프로젝트로 옮긴
버전으로, Vercel 같은 곳에 그대로 배포해서 학교 코드로 접속하는 실제 웹사이트로 쓸 수
있습니다.

이 문서는 컴퓨터 작업에 아주 익숙하지 않아도 따라 할 수 있도록 순서대로 적었습니다.
막히는 단계가 있으면 그 단계까지만 하고 캡처해서 물어보셔도 됩니다.

---

## 0. 이 버전에서 무엇이 바뀌었는지

- **저장소**: Claude 전용 저장소(`window.storage`) → **Firebase Firestore**로 교체했습니다.
  화면·기능 코드는 거의 그대로이고, "어디에 저장하느냐"만 바뀌었습니다.
- **학생 실명 보호**: Firestore(외부 상업 클라우드)에는 학생 **이름을 저장하지 않습니다.**
  저장되는 값은 익명 id·학년·반·번호·성별·측정기록뿐이고, 실명은 **이 기기(브라우저)의
  로컬 저장소**에만 남아 화면 표시용으로만 쓰입니다. 자세한 내용은 3번 섹션을 참고하세요.
- **문의하기**: 버튼을 누르면 준비해 두신 구글 폼(`https://forms.gle/hEwyNGdcMKjtMTWu8`)이
  새 탭에서 열립니다.
- **빔프로젝터 고정모드**: 같은 창을 전체화면으로 바꾸는 대신, 전광판 전용 **새 창**을
  띄웁니다. 그 창을 빔프로젝터로 옮겨두고, 원래 창(노트북)에서는 계속 다른 작업을 할 수
  있습니다. 두 창은 같은 Firestore 데이터를 보므로 자연스럽게 동기화됩니다.
- **모바일 홈 화면 설치(PWA)**: "모바일로 함께 보기" 화면에 설치 버튼을 추가했습니다.
  안드로이드는 버튼 한 번으로 설치되고, 아이폰은 애플 정책상 "공유 → 홈 화면에 추가"를
  직접 눌러야 한다는 안내만 보여줍니다.
- **데이터 백업**: 기존 "실명 포함(교사 보관용)" 내보내기에 더해, 이름 대신 "1학년 1반
  2번" 형태만 담는 **"익명화(외부 공유용)" 내보내기**가 추가되었습니다.
- 그 외 기록입력·등급표·전광판·접근권한·나이스 양식 반영·반응형 디자인 등은 기존 기능을
  그대로 가져왔습니다.

## 2. Firebase 설정 (가장 중요한 단계)

### 2-1. Firestore 데이터베이스 만들기

1. https://console.firebase.google.com 에서 `smart-paps` 프로젝트를 엽니다.
2. 왼쪽 메뉴 **Firestore Database** → **데이터베이스 만들기**를 누릅니다.
3. 위치는 서울 등 가까운 리전을 선택하고, **프로덕션 모드**로 시작합니다(어차피 아래에서
   보안 규칙을 직접 덮어씁니다).

### 2-2. 보안 규칙 배포하기 (꼭 필요합니다)

이 프로젝트에는 `firestore.rules` 파일이 함께 들어있습니다. 이 프로그램이 실제로 쓰는
`paps:`로 시작하는 키만 읽고 쓸 수 있게 제한하는 최소한의 안전장치입니다. **이걸 배포하지
않으면 기본 규칙(테스트 모드는 완전 공개, 프로덕션 모드는 완전 차단) 중 하나가 그대로
적용되어 프로그램이 아예 안 되거나, 반대로 너무 열려있게 됩니다.**

**콘솔에서 직접 붙여넣는 방법(가장 쉬움):**

1. Firebase 콘솔 → Firestore Database → 상단 탭 **규칙(Rules)**
2. 이 프로젝트의 `firestore.rules` 파일 내용을 전부 복사해서 붙여넣기
3. **게시(Publish)** 클릭

**또는 커맨드라인으로 배포하는 방법:**

```bash
npm install -g firebase-tools
firebase login
firebase deploy --only firestore:rules
```
(이 프로젝트 폴더 안에서 실행하세요. `firebase.json`이 이미 `firestore.rules`를
가리키도록 설정되어 있습니다.)

> **보안 관련 참고**: 이 프로그램은 Firebase 로그인 없이 "학교 코드 + 접근 신청
> 비밀번호"라는 자체 방식으로 접근을 통제합니다. 그래서 이 보안 규칙은 "이 프로그램이 쓰는
> 키만 저장 가능"하다는 정도의 최소한의 보호막이고, 코드 자체를 아는 사람은 그 학교
> 데이터에 접근할 수 있다는 신뢰 모델은 원래 Claude 버전과 동일합니다(학생 실명은 애초에
> 서버에 없으므로 유출되어도 실명이 노출되지는 않습니다). 실제 학교 도입 전에는 학교·교육청
> 개인정보 담당자와 한 번 확인해 보시길 권합니다.

### 2-3. 웹 앱 설정값

`src/firebase.js`에 이미 알려주신 `firebaseConfig` 값이 그대로 들어가 있습니다. 이 값은
브라우저 코드에 공개적으로 들어가도록 설계된 값이라(진짜 보안은 위 2-2번 규칙이 담당) 별도
조치가 필요 없습니다.

## 3. 학생 실명은 어떻게 보호되나요?

- Firestore에 저장되는 학생 정보: `id`(익명 고유키), `grade`, `classNum`, `number`,
  `gender`, 그리고 측정기록뿐입니다. **이름은 절대 서버로 전송되지 않습니다.**
- 학생을 등록하거나 명단을 엑셀로 올리면, 그 순간 **그 컴퓨터(브라우저)의 로컬 저장소**에
  "학생 id → 이름" 표가 만들어지고, 화면에는 그 표를 참고해서 이름이 정상적으로 보입니다.
- **다른 컴퓨터**(동료 선생님 컴퓨터 등)에서 같은 학교 코드로 처음 접속하면, 아직 그
  컴퓨터에는 이름표가 없으므로 학생 이름이 `(이름 미확인 - 이 기기)`로 보입니다. 이때는
  데이터 백업 탭에서 "JSON으로 내보내기(교사 보관용, 실명 포함)" 파일을 그 컴퓨터에서
  한 번 "불러오기" 하면 그 컴퓨터에도 이름표가 채워집니다.
- 전광판·포디움·빔프로젝터 화면 등 학생·관람객에게 보이는 화면은 원래부터 실명 대신
  `[1학년 1반 2번]` 형태로만 표시되며, 이 버전에서도 그대로 유지됩니다.
- 데이터 백업 탭에서 "익명화(외부 공유용)" 내보내기를 고르면, 이름 대신 학급·번호 라벨만
  담긴 파일을 받을 수 있습니다(이 파일은 다시 불러오기 용도로는 쓸 수 없습니다 — 실명이
  필요 없는 통계 공유·제출용입니다).

## 6. Vercel에 배포하기

1. https://vercel.com 에 GitHub 계정으로 로그인합니다.
2. **Add New → Project**를 누르고, 방금 올린 `smart-paps` 저장소를 선택합니다.
3. Framework Preset이 자동으로 **Vite**로 인식됩니다(안 되면 직접 Vite로 선택). 빌드
   명령(`npm run build`)과 출력 폴더(`dist`)도 자동으로 채워집니다 — 그대로 두면 됩니다.
4. 환경변수는 따로 설정할 필요 없습니다(Firebase 설정값이 이미 코드 안에 들어있습니다).
5. **Deploy**를 누르면 몇 분 안에 `https://smart-paps-xxxx.vercel.app` 같은 실제 주소가
   생깁니다. 이 주소가 이제 학교에서 계속 쓸 "프로그램 링크"입니다.

이후 코드를 수정하고 싶으면, 로컬에서 고친 뒤 다시 `git push`만 하면 Vercel이 자동으로
새로 배포합니다.

### 나만의 도메인을 쓰고 싶다면

Vercel 프로젝트 설정의 **Domains**에서 학교나 개인이 가진 도메인을 연결할 수 있습니다
(선택 사항입니다).

## 8. 프로젝트 구조

```
smart-paps/
  index.html            앱 진입 HTML (PWA 메타태그 포함)
  package.json
  vite.config.js
  firebase.json          Firebase CLI 설정(규칙 배포용)
  firestore.rules         Firestore 보안 규칙
  firestore.indexes.json
  public/
    manifest.webmanifest  PWA 매니페스트
    sw.js                 서비스워커(설치 가능 조건 충족용, 최소 캐싱만)
    icons/                PWA 아이콘(192/512/마스커블). 원하시면 학교 로고 등으로 교체 가능
  src/
    main.jsx              앱 진입점 (URL의 ?present=1&code=... 처리, 서비스워커 등록)
    App.jsx                기존 paps_dashboard.jsx 전체 기능(화면·로직) + 이번에 추가된 부분
    firebase.js            Firebase 초기화
    storage.js              기존 window.storage와 동일한 모양의 저장소 계층
                             (shared:true → Firestore, shared:false → 이 브라우저의 localStorage)
    pwaInstall.js           홈 화면 설치 버튼을 위한 훅
```

`App.jsx`는 기존 코드 구조를 그대로 유지했습니다 — 화면·기능을 고치고 싶으실 때, 원래
아티팩트를 보시던 것과 같은 방식으로 찾아서 수정하시면 됩니다.

## 9. 앞으로 더 손볼 수 있는 부분 (참고)

- **실시간 동기화 주기**: 지금은 기존 버전과 동일하게 10초마다 서버 값을 다시 받아오는
  방식입니다(빔프로젝터 새 창도 이 주기로 맞춰집니다). Firestore의 실시간 구독(`onSnapshot`)
  기능을 쓰면 이 지연을 거의 0으로 줄일 수 있는데, 이번 전환에서는 기존 동작을 최대한
  그대로 유지하는 쪽을 택했습니다. 필요하시면 다음 단계로 요청해 주세요.
- **PWA 아이콘**: `public/icons/`에 기본 아이콘을 만들어 두었습니다. 학교 로고 등으로
  바꾸고 싶으시면 같은 파일명(192×192, 512×512, 마스커블 512×512 PNG)으로 교체하시면
  됩니다.
- **더 강한 보안**: 지금은 Firebase 로그인 없이 "코드=비밀키" 방식입니다. 여러 학교가
  대규모로 쓰게 되면 Firebase Authentication 도입을 고려해볼 수 있습니다.
