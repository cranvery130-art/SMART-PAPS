# SMART PAPS — 독립 웹사이트 버전

중학교 체육수업용 PAPS(팝스) 실시간 기록·랭킹 관리 프로그램입니다. 기존 Claude 아티팩트
(`paps_dashboard.jsx`)를 React + Firebase(Firestore) 기반의 독립 웹 프로젝트로 옮긴
버전으로, Vercel 같은 곳에 그대로 배포해서 학교 코드로 접속하는 실제 웹사이트로 쓸 수
있습니다.

이 문서는 컴퓨터 작업에 아주 익숙하지 않아도 따라 할 수 있도록 순서대로 적었습니다.
막히는 단계가 있으면 그 단계까지만 하고 캡처해서 물어보셔도 됩니다.

---

## 0. 이 버전에서 무엇이 바뀌었는지

- **저장소**: Claude 전용 저장소(`window.storage`) → **Firebase Firestore**로 교체했습니다.
  화면·기능 코드는 거의 그대로이고, "어디에 저장하느냐"만 바뀌었습니다.
- **학생 실명 보호**: Firestore(외부 상업 클라우드)에는 학생 **이름을 저장하지 않습니다.**
  저장되는 값은 익명 id·학년·반·번호·성별·측정기록뿐이고, 실명은 **이 기기(브라우저)의
  로컬 저장소**에만 남아 화면 표시용으로만 쓰입니다. 자세한 내용은 3번 섹션을 참고하세요.
  다만 학년·반·번호만으로도 학교 안에서는 누구인지 알 수 있어서, 서버에 있는 기록도 여전히
  **개인정보**입니다(개인정보 보호법 제2조제1호 나목). 학교 코드·비밀번호를 학생에게 알리지 마세요.
- **건강 정보는 이 기기에만(2026-10)**: 신장·체중·BMI·체지방률(과 그 값으로 계산하는 비만도 분류)은
  Firestore에 **올리지 않고**, 입력한 기기(브라우저)에만 저장합니다. 다른 기기에서는 "이 기기에 없음"으로
  보이고, 왕복오래달리기·악력 같은 나머지 종목은 지금처럼 모든 기기에 공유됩니다. 자세한 내용은 3-1번을 보세요.
- **로그인 보안(2026-10 개편)**: 모든 기기가 Firebase **익명 로그인**(이름·이메일 없음)을 하고,
  비밀번호는 원문 대신 **SHA-256 해시**로만 저장합니다. 비밀번호가 맞는지, 누가 조회·수정·승인할
  수 있는지는 화면이 아니라 **Firestore 보안 규칙(서버)**이 직접 확인합니다. 자세한 내용은 2-2번을 보세요.
- **문의하기**: 버튼을 누르면 준비해 두신 구글 폼(`https://forms.gle/hEwyNGdcMKjtMTWu8`)이
  새 탭에서 열립니다.
- **빔프로젝터 고정모드**: 같은 창을 전체화면으로 바꾸는 대신, 전광판 전용 **새 창**을
  띄웁니다. 그 창을 빔프로젝터로 옮겨두고, 원래 창(노트북)에서는 계속 다른 작업을 할 수
  있습니다. 두 창은 같은 Firestore 데이터를 보므로 자연스럽게 동기화됩니다.
- **모바일 홈 화면 설치(PWA)**: "모바일로 함께 보기" 화면에 설치 버튼을 추가했습니다.
  안드로이드는 버튼 한 번으로 설치되고, 아이폰은 애플 정책상 "공유 → 홈 화면에 추가"를
  직접 눌러야 한다는 안내만 보여줍니다.
- **데이터 백업**: "JSON으로 내보내기(교사 보관용, 실명 포함)"로 이 기기에 백업 파일을 저장합니다.
- **사용 가이드 · 연습모드**: 사용설명서·기능설명·상세설명을 "사용 가이드" 하나로 합쳤습니다(첫
  화면 버튼 + 프로그램 안 탭). 단계마다 데모 화면에 번호를 붙여 따라 하기 쉽게 했고, 첫 화면의
  "연습모드 체험"으로 가짜 학생 34명이 들어 있는 연습중학교를 직접 눌러볼 수 있습니다. 연습
  데이터는 서버로 보내지 않고 그 기기(브라우저)에만 저장되며, "연습 끝내기"를 누르면 지워집니다.
- 그 외 기록입력·등급표·전광판·접근권한·나이스 양식 반영·반응형 디자인 등은 기존 기능을
  그대로 가져왔습니다.

## 2. Firebase 설정 (가장 중요한 단계)

### 2-1. Firestore 데이터베이스 만들기

1. https://console.firebase.google.com 에서 `smart-paps` 프로젝트를 엽니다.
2. 왼쪽 메뉴 **Firestore Database** → **데이터베이스 만들기**를 누릅니다.
3. 위치는 서울 등 가까운 리전을 선택하고, **프로덕션 모드**로 시작합니다(어차피 아래에서
   보안 규칙을 직접 덮어씁니다).

### 2-2. 익명 로그인 켜기 + 보안 규칙 배포하기 (꼭 필요합니다)

**적용 순서(처음 한 번, 이 순서대로):**

1. Firebase 콘솔 → **Authentication** → (처음이면 "시작하기") → **로그인 방법(Sign-in method)** 탭 →
   **익명(Anonymous)** → 사용 설정 → 저장
2. Firestore Database → **규칙(Rules)** 탭에서 지금 규칙을 복사해 따로 보관해 둔 뒤(되돌릴 때 필요),
   이 프로젝트의 `firestore.rules` 내용을 전부 붙여넣고 **게시(Publish)**
3. 새 버전을 배포(Vercel)하고, 개설자가 **각 학교 코드마다 한 번** "코드로 로그인"에 코드와 개설자 전용
   비밀번호를 입력합니다. 이때 예전 데이터가 새 방식으로 옮겨집니다(아래 "예전 코드 옮기기").

1번을 빼먹으면 모든 기기가 로그인하지 못해 아무것도 열리지 않습니다. 2번과 3번 사이(몇 분)에는 예전
버전 화면이 동작하지 않으니, 수업이 없는 시간에 하세요.

**커맨드라인으로 규칙을 배포하는 방법(선택):**

```bash
npm install -g firebase-tools
firebase login
firebase deploy --only firestore:rules
```
(이 프로젝트 폴더 안에서 실행하세요. `firebase.json`이 이미 `firestore.rules`를 가리키도록 설정되어
있습니다. 익명 로그인 켜기(1번)는 콘솔에서 해야 합니다.)

**Firestore 구조:**

| 위치 | 내용 | 누가 읽고 쓰나 |
|---|---|---|
| `schools/{코드}/meta/info` | 코드가 있는지, 접근 신청이 켜져 있는지(`viewerOn`) — 비밀번호 없음 | 읽기: 로그인한 기기 누구나 / 쓰기: 개설자 |
| `schools/{코드}/meta/secret` | 개설자·접근 신청 비밀번호의 SHA-256 해시 | **아무도 읽을 수 없음** / 쓰기: 개설자 |
| `schools/{코드}/claims/{uid}` | 들어올 때 기기가 계산해 제출하는 해시(5초에 한 번만) | 본인만 쓰기, 아무도 읽지 못함(마감 때 개설자가 지움) |
| `schools/{코드}/members/{uid}` | 구성원: 개설자·수정 권한·조회 전용·승인 대기·거절, 신청 이름 | 본인·개설자·수정 권한자 읽기 / 승인·거절·취소는 개설자 |
| `schools/{코드}/data/config` | 학생 명단(이름 제외)·등급 기준·설정(비밀번호 없음) | 읽기: 승인된 구성원 / 쓰기: 개설자·수정 권한자 |
| `schools/{코드}/data/records` | 측정 기록(신장·체중·BMI·체지방률은 값 없이 "측정했음" 표시만) | 읽기: 승인된 구성원 / 쓰기: 개설자·수정 권한자 |
| `schools/{코드}/data/auditlog`, `backuplog` | 변경 이력(최근 300건, BMI·체지방률은 바뀐 값 없이)·백업 이력(최근 30건) | 개설자·수정 권한자 |
| `kv/paps:stats:*` | 방문 집계(숫자) | 로그인한 기기 누구나 |

`uid`는 익명 로그인 기기 번호입니다. 같은 브라우저에서는 유지되고(빔프로젝터 새 창도 같은 기기로
인정), 브라우저 데이터를 지우거나 시크릿 창·다른 기기에서는 새 번호가 생겨 다시 들어와야 합니다.

**어떻게 지켜지나요?**
- 비밀번호는 원문으로 저장하지 않습니다(개인정보의 안전성 확보조치 기준 제7조①). 코드·종류별로 섞어서
  해시하므로 같은 비밀번호라도 저장값이 다릅니다. 그래서 개설자 본인도 지금 비밀번호를 다시 볼 수 없고,
  "접근권한" 탭에서는 새 비밀번호로 **바꾸기만** 할 수 있습니다.
- 들어올 때 기기가 계산한 해시를 규칙이 저장된 해시와 비교해야 구성원 문서가 만들어집니다. 틀린 비밀번호는
  서버에서 5초에 한 번만 다시 시도할 수 있고, 한 기기에서 5번 틀리면 화면에서 10분 동안 막습니다.
- 조회 전용·승인 대기·권한이 취소된 기기는 서버에서 데이터를 쓸 수 없고, 승인 대기·취소된 기기와 코드만 아는
  사람은 명단·기록을 읽을 수도 없습니다.
- 빔프로젝터 화면 잠금과 공용 PC 자동 잠금도 접근 신청 비밀번호를 서버 규칙으로 확인해서 풉니다.
- 학생 실명은 서버에 저장하지 않습니다(3번 참고). 신장·체중·BMI·체지방률도 서버에 저장하지 않습니다(3-1번 참고).
  다만 이건 앱이 보내기 전에 빼내는 방식이고, 보안 규칙이 막지는 않습니다(측정 기록이 JSON 글자 한 덩어리라
  규칙에서 안쪽을 검사하려면 큰 글자열 전체에 정규식을 돌려야 해서, 기록 저장이 통째로 막힐 위험이 있어 넣지 않았습니다).

**예전 코드 옮기기(개편 전 코드):** 예전에는 `kv/paps:config:{코드}` 등 `kv` 문서에 비밀번호 원문이 설정과 함께
들어 있었습니다. 새 규칙을 게시하면 이 문서들은 그 코드의 개설자 말고는 읽을 수 없게 되고, 개설자가 새 버전에서
개설자 전용 비밀번호로 처음 로그인하는 순간 명단·설정·기록·변경 이력·백업 이력이 `schools/{코드}/...`로 옮겨지고
비밀번호는 해시로 바뀌며 예전 `kv` 문서(비밀번호 원문 포함)는 지워집니다.
- **모든 기기가 한 번 다시 들어와야 합니다.** 개설자는 기기마다 "코드로 로그인", 동료 선생님은 개설자가 옮긴 뒤
  "접근 신청"을 다시 하고, **수정 권한은 개설자가 다시 승인**해야 합니다(예전 신청 목록은 옮기지 않습니다).
- 옮기기 전에는 동료 선생님이 그 코드로 접근 신청을 할 수 없습니다.
- 예전에 **개설자 전용 비밀번호를 비워 두고 만든 코드**는 새 방식으로 옮길 수 없습니다(누가 개설자인지 서버가
  확인할 방법이 없음). 새 규칙을 게시하기 **전에** 예전 버전의 "접근권한" 탭에서 개설자 전용 비밀번호를 정해 두세요.
- 비밀번호에 큰따옴표(`"`)가 들어 있으면 옮기기가 되지 않습니다. 이 경우도 게시 전에 비밀번호를 바꿔 두세요.

### 2-3. 웹 앱 설정값

`src/firebase.js`에 이미 알려주신 `firebaseConfig` 값이 그대로 들어가 있습니다. 이 값은
브라우저 코드에 공개적으로 들어가도록 설계된 값이라(진짜 보안은 위 2-2번 익명 로그인과 규칙이 담당)
별도 조치가 필요 없습니다.

## 3. 학생 실명은 어떻게 보호되나요?

- Firestore에 저장되는 학생 정보: `id`(익명 고유키), `grade`, `classNum`, `number`,
  `gender`, 그리고 측정기록뿐입니다. **이름은 절대 서버로 전송되지 않습니다.**
- 학생을 등록하거나 명단을 엑셀로 올리면, 그 순간 **그 컴퓨터(브라우저)의 로컬 저장소**에
  "학생 id → 이름" 표가 만들어지고, 화면에는 그 표를 참고해서 이름이 정상적으로 보입니다.
- **다른 컴퓨터**(동료 선생님 컴퓨터 등)에서 같은 학교 코드로 처음 접속하면, 아직 그
  컴퓨터에는 이름표가 없으므로 학생 이름이 `(이름 미확인 - 이 기기)`로 보입니다. 이때는
  데이터 백업 탭에서 "JSON으로 내보내기(교사 보관용, 실명 포함)" 파일을 그 컴퓨터에서
  한 번 "불러오기" 하면 그 컴퓨터에도 이름표가 채워집니다.
- 전광판·포디움·빔프로젝터 화면 등 학생·관람객에게 보이는 화면은 원래부터 실명 대신
  `[1학년 1반 2번]` 형태로만 표시되며, 이 버전에서도 그대로 유지됩니다.
- 실명이 빠져 있어도 학년·반·번호·성별·측정기록은 개인정보입니다. 특히 신장·체중·BMI·체지방률은
  건강에 관한 정보라 더 조심해야 합니다. 백업 파일은 학교 업무용 PC에만 두고, 구글 드라이브 같은
  클라우드나 메신저로 옮기지 마세요(경남교육청 개인정보 처리 유의사항).
- 사용 기록 분석(Google 애널리틱스)은 쓰지 않습니다. 학생·교사의 사용 기록을 외부 분석 서비스로 보내지 않습니다.

### 3-1. 건강 정보(신장·체중·BMI·체지방률)는 이 기기에만

학교 개인정보 처리 안내(민감한 건강 정보는 클라우드에 올리지 않음)에 따라, 건강 정보는 Firestore로 보내지 않습니다.

- **저장 위치**: 입력한 기기 브라우저의 로컬 저장소(`paps:health:{코드}`)에 학생 id·종목·연도별로 저장합니다.
  서버의 측정 기록에는 값 없이 "측정했음" 표시(`localOnly`, 측정 시각, 측정 당시 학년)만 남습니다. 비만도 분류
  (마름·정상·과체중·경도비만·고도비만)는 값에서 그때그때 계산하므로 따로 저장하지 않습니다.
- **다른 기기에서는**: 그 학생의 BMI·체지방률이 "이 기기에 없음"으로 보입니다. 나머지 종목은 그대로 공유됩니다.
  두 기기에서 같은 학생의 BMI를 각각 입력하면 기기마다 자기 값이 보이니, **건강 종목은 학교 업무용 PC 한 대에서만
  입력**하세요. 변경 이력에도 BMI·체지방률은 "누가 언제 바꿨는지"만 서버에 남고, 바뀐 값과 되돌리기는 입력한 기기에서만 보입니다.
- **다른 PC로 옮기기**: 데이터 백업 탭의 **"건강 기록 내보내기"**로 파일을 받아, 다른 PC에서 같은 코드로 들어와
  **"건강 기록 파일 불러오기"**를 누르세요(이름은 들어 있지 않고, 같은 코드에서만 불러올 수 있습니다). 이 파일은
  학교 업무용 PC에만 두고, 구글 드라이브 같은 클라우드·메신저·이메일로 옮기지 말고, 옮긴 뒤에는 지우세요.
- **나이스 양식·엑셀·JSON 백업**: 이 기기에 있는 건강 값은 지금처럼 들어갑니다(다른 기기 값은 빈칸).
- **브라우저 데이터를 지우면** 이 기기의 건강 기록도 사라집니다. 파일로 한 번 받아 두세요.
- **예전 데이터 정리(한 번만)**: 이 버전 이전에 서버에 올라간 건강 값은, 개설자나 수정 권한자가 새 버전에서
  그 코드를 처음 열 때 **그 기기로 옮겨지고 서버에서는 지워집니다.** 먼저 그 기기에 저장하고 다시 읽어 확인한 뒤에만
  서버 기록을 고치며, 확인이 안 되면 서버는 그대로 둡니다(다음에 열 때 다시 시도). 옮긴 기기는 변경 이력에
  "OO님 기기로 건강 기록 N건을 옮김"으로 남습니다. **건강 기록을 둘 PC(보통 개설자의 학교 업무용 PC)에서 먼저 열어 주세요.**
- **마감**: 마감한 기기의 건강 기록은 함께 지워지고, 다른 기기의 건강 기록은 그 기기에서 프로그램을 다시 열어
  "없는 코드"로 확인될 때 지워집니다.

## 6. Vercel에 배포하기

1. https://vercel.com 에 GitHub 계정으로 로그인합니다.
2. **Add New → Project**를 누르고, 방금 올린 `smart-paps` 저장소를 선택합니다.
3. Framework Preset이 자동으로 **Vite**로 인식됩니다(안 되면 직접 Vite로 선택). 빌드
   명령(`npm run build`)과 출력 폴더(`dist`)도 자동으로 채워집니다 — 그대로 두면 됩니다.
4. 환경변수는 따로 설정할 필요 없습니다(Firebase 설정값이 이미 코드 안에 들어있습니다).
5. **Deploy**를 누르면 몇 분 안에 `https://smart-paps-xxxx.vercel.app` 같은 실제 주소가
   생깁니다. 이 주소가 이제 학교에서 계속 쓸 "프로그램 링크"입니다.

이후 코드를 수정하고 싶으면, 로컬에서 고친 뒤 다시 `git push`만 하면 Vercel이 자동으로
새로 배포합니다.

### 나만의 도메인을 쓰고 싶다면

Vercel 프로젝트 설정의 **Domains**에서 학교나 개인이 가진 도메인을 연결할 수 있습니다
(선택 사항입니다).

## 7. 배포 후 확인 체크리스트

- [ ] 학교 코드를 새로 만들어 접속되는지
- [ ] 학생 등록 → 기록 입력 → 등급표에 반영되는지
- [ ] Authentication → 사용자 탭에 익명 사용자가 생기는지(로그인이 되는지)
- [ ] 예전 코드는 개설자가 "코드로 로그인"으로 한 번 들어가 옮겨지는지(Firestore에 `schools/{코드}`가 생기고 `kv/paps:config:{코드}`가 사라지는지)
- [ ] 다른 브라우저(또는 시크릿 창)에서 같은 코드로 "접근 신청"이 되는지, 틀린 비밀번호는 거절되는지
- [ ] "빔프로젝터 고정모드"를 누르면 새 창이 열리고, 그 창이 자동으로 잠기는지(접근 신청
      비밀번호를 설정해 둔 경우)
- [ ] 스마트폰에서 주소를 열어 "모바일로 함께 보기" → 홈 화면 설치가 되는지
- [ ] 나이스 양식 업로드·반영이 잘 되는지
- [ ] 데이터 백업(실명 포함) 다운로드가 되는지
- [ ] BMI·체지방률을 입력한 뒤 Firestore 콘솔의 `schools/{코드}/data/records` 값에 신장·체중·BMI·체지방률 숫자가
      없고 `"localOnly":true` 표시만 있는지, 다른 기기에서는 "이 기기에 없음"으로 보이는지
- [ ] 데이터 백업 탭의 "건강 기록 내보내기 → 다른 PC에서 불러오기"가 되는지
- [ ] Firestore 콘솔의 **사용량(Usage)** 탭에서 읽기/쓰기 횟수가 무료 한도 안에 있는지
      (학교 하나 규모 사용량이면 거의 항상 무료 범위 안입니다)

## 8. 프로젝트 구조

```
smart-paps/
  index.html            앱 진입 HTML (PWA 메타태그 포함)
  package.json
  vite.config.js
  firebase.json          Firebase CLI 설정(규칙 배포용)
  firestore.rules         Firestore 보안 규칙
  firestore.indexes.json
  public/
    manifest.webmanifest  PWA 매니페스트
    sw.js                 서비스워커(설치 가능 조건 충족용, 최소 캐싱만)
    icons/                PWA 아이콘(192/512/마스커블). 원하시면 학교 로고 등으로 교체 가능
  src/
    main.jsx              앱 진입점 (URL의 ?present=1&code=... 처리, 서비스워커 등록)
    App.jsx                기존 paps_dashboard.jsx 전체 기능(화면·로직) + 이번에 추가된 부분
    firebase.js            Firebase 초기화 + 익명 로그인(ensureSignedIn)
    storage.js              기존 window.storage와 동일한 모양의 저장소 계층
                             (shared:true → Firestore schools/{코드}/data/*, shared:false → 이 브라우저의 localStorage)
                             + 접근 권한 함수(코드 만들기, 개설자 로그인, 접근 신청, 비밀번호 바꾸기, 예전 코드 옮기기, 마감)
    healthLocal.js          신장·체중·BMI·체지방률을 서버로 보내기 전에 빼서 이 기기에만 저장·합치기,
                             예전 서버 값 옮기기, 건강 기록 파일 내보내기·불러오기
    pwaInstall.js           홈 화면 설치 버튼을 위한 훅
```

`App.jsx`는 기존 코드 구조를 그대로 유지했습니다 — 화면·기능을 고치고 싶으실 때, 원래
아티팩트를 보시던 것과 같은 방식으로 찾아서 수정하시면 됩니다.

## 9. 앞으로 더 손볼 수 있는 부분 (참고)

- **실시간 동기화 주기**: 지금은 기존 버전과 동일하게 10초마다 서버 값을 다시 받아오는
  방식입니다(빔프로젝터 새 창도 이 주기로 맞춰집니다). Firestore의 실시간 구독(`onSnapshot`)
  기능을 쓰면 이 지연을 거의 0으로 줄일 수 있는데, 이번 전환에서는 기존 동작을 최대한
  그대로 유지하는 쪽을 택했습니다. 필요하시면 다음 단계로 요청해 주세요.
- **PWA 아이콘**: `public/icons/`에 기본 아이콘을 만들어 두었습니다. 학교 로고 등으로
  바꾸고 싶으시면 같은 파일명(192×192, 512×512, 마스커블 512×512 PNG)으로 교체하시면
  됩니다.
- **더 강한 보안**: 지금은 익명 로그인 + 비밀번호 해시 방식입니다. 학교 코드와 비밀번호를 아는 사람은
  (조회는 바로, 수정은 승인 후) 들어올 수 있으므로 둘 다 학생에게 알리지 마세요. 여러 학교가 대규모로
  쓰게 되면 학교 계정(구글 워크스페이스 등) 로그인 도입을 고려해볼 수 있습니다.
